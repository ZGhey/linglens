Server Rendering and Hydration

Send real HTML first, then make it interactive.

With server rendering, your components run on the server and the browser receives finished HTML, so the page appears before any JavaScript loads. React then performs hydration: it attaches event handlers and state to the HTML that is already there instead of re-creating it.

Hydration mismatches

If the HTML the server produced differs from what the client renders on its first pass, React reports a mismatch and may discard the server markup. Keep the first client render identical — read window, dates or random values only in an effect.

import { hydrateRoot } from 'react-dom/client'
hydrateRoot(document.getElementById('root'), <App />)

Streaming

Streaming sends HTML in chunks as each part of the tree is ready, and selective hydration lets React make the parts the user interacts with first become interactive first.
